# Shared prepared portal price artifacts — 15 November 2026

Production deploy `6af9aa60d4a45c244b6d77a0` and migration `shared_prepared_customer_price_artifacts` allow an already finalized customer workbook to be reused across customer invitations, only when tenant, brand identity, source version, list type, effective numeric margin, EUR currency, format and version contract match. The server first resolves the requesting invitation and pricing context, and a service-only SQL RPC verifies current source and Storage metadata before issuing a separate customer-scoped finalized receipt pointing to the same bytes. Existing download authorization still checks each invitation and brand. Existing files and receipts are preserved. Matching active jobs are not coalesced across different customer accounts: simultaneous cold requests can still create separate work before either artifact exists. First-time accounts can reuse an existing matching artifact on request; this does not proactively enumerate every customer/brand combination.

Follow-up deployment `6af9b0d4034e26d98ac7f95e` supersedes the preceding limitation: equivalent cold requests are serialized by shared price scope. The first receipt is the producer; each other customer receives a separate follower receipt, and the producer's terminal update finalizes or fails its followers in the same transaction. Source freshness is checked at finalization and the follower's current account context is rechecked on status/download. Expired or missing producers can release orphan followers for retry. Followers are excluded from dispatch and recovery.
